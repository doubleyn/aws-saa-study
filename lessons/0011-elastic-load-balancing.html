무엇을 보고 나누나:
ALB vs NLB vs GWLB

세 로드 밸런서는 이름이 비슷하지만 보는 계층이 다릅니다. ALB는 HTTP 요청의 내용을, NLB는 연결을, GWLB는 패킷을 봅니다. 이 한 줄이 시험 문제의 80%를 풉니다.

왜 이것부터인가

시험에서: "경로별 라우팅", "고정 IP", "UDP", "서드파티 방화벽" 같은 단어 하나로 정답이 갈립니다. 다음 레슨(Auto Scaling)도 로드 밸런서의 대상 그룹과 상태 확인을 전제로 합니다.
실무에서: 다중 AZ 고가용성 웹 아키텍처의 정문입니다. 잘못 고르면 나중에 IP 화이트리스트나 라우팅 요구를 맞추느라 앞단을 갈아엎게 됩니다.

공통 구조: 리스너 → 규칙 → 대상 그룹

로드 밸런서는 리스너(프로토콜+포트)로 연결을 받고, 규칙에 따라 대상 그룹으로 보냅니다. 대상 그룹마다 상태 확인을 설정하며, 로드 밸런서는 정상(healthy) 대상에게만 트래픽을 보냅니다. 한 대상을 여러 대상 그룹에 등록할 수도 있습니다.[2] AZ를 활성화하면 그 AZ에 로드 밸런서 노드가 생기고, 활성화하지 않은 AZ의 대상은 트래픽을 받지 못합니다. ALB는 최소 2개 AZ를 활성화해야 합니다.[1]

인터넷 경계(internet-facing) 로드 밸런서의 노드는 퍼블릭 IP를, 내부(internal) 로드 밸런서의 노드는 프라이빗 IP만 가집니다. 어느 쪽이든 대상에는 프라이빗 IP로 보내므로 대상에 퍼블릭 IP가 필요 없습니다. 웹 계층은 인터넷 경계, 앱 계층은 내부 로드 밸런서로 두는 다계층 구성이 AWS 문서의 예시입니다.[1]

ALB만의 기능

  • 경로 기반(/img/*)과 호스트 기반(*.example.com) 라우팅. 하나의 ALB로 여러 서비스·여러 도메인을 처리합니다.[4]
  • 리디렉션, 고정 응답 반환, 기업·소셜 ID로 사용자 인증 후 라우팅, ACM 인증서로 HTTPS 종료, AWS WAF 연동.[2]
  • Lambda 대상: 대상 그룹 하나에 함수 하나만 등록하고, 요청 본문과 응답 JSON은 각각 최대 1 MB입니다. Lambda 대상 그룹은 상태 확인이 기본으로 꺼져 있습니다.[10]
  • ip 대상으로 피어링된 VPC의 인스턴스나 Direct Connect·VPN으로 연결된 온프레미스 서버도 등록할 수 있습니다. 단, 퍼블릭 라우팅 가능 IP는 안 됩니다.[3]

GWLB는 Gateway Load Balancer 엔드포인트(VPC 엔드포인트의 일종)를 라우팅 테이블의 다음 홉으로 지정해 다른 VPC의 트래픽을 어플라이언스 VPC로 보냈다가 돌려받습니다.[7]

대상 그룹의 대상이 전부 비정상이면 ALB는 상태와 무관하게 모든 대상에 보냅니다(fail open).[8]

  • 등록 취소 지연(deregistration delay, 연결 드레이닝): 등록 취소되는 대상은 draining 상태가 되어 새 요청을 받지 않고, 진행 중 요청이 끝나기를 기본 300초 기다립니다.[9]
  • 느린 시작(slow start): 새로 정상이 된 대상에 트래픽을 선형으로 늘려 예열 시간을 줍니다.[9]
  • 고정 세션(sticky sessions, 세션 선호도): 쿠키로 한 사용자의 요청을 같은 대상에 묶습니다. 대상 그룹 수준에서 켜며, ALB가 만드는 AWSALB 쿠키(기간 기반) 또는 애플리케이션 쿠키(애플리케이션 기반)를 씁니다. 클라이언트가 쿠키를 지원해야 하고, 교차 영역을 끈 대상 그룹에서는 쓸 수 없습니다. 대상이 비정상이 되면 새 대상을 고릅니다.[9] NLB의 고정 세션은 소스 IP 기준이라, 같은 NAT 뒤 클라이언트가 한 대상에 몰릴 수 있습니다.[6]

연습

Q1. 회사의 웹 애플리케이션이 /api/* 요청은 주문 서비스로, /images/* 요청은 이미지 서비스로 보내야 합니다. 두 서비스는 각각 다른 EC2 Auto Scaling 그룹에서 실행됩니다. 운영 부담이 가장 적은 구성은?

URL 경로를 보는 것은 7계층 ALB의 path-pattern 조건입니다. 규칙마다 다른 대상 그룹으로 보내면 ALB 하나로 끝납니다. NLB는 4계층이라 HTTP 경로를 볼 수 없으니 "NLB에 경로 규칙"은 존재하지 않는 기능이고, NLB 두 개는 관리 대상만 늘립니다. GWLB는 보안 어플라이언스용입니다.

Q2. 실시간 멀티플레이 게임 서버가 UDP로 통신하며 초당 수백만 패킷을 처리해야 합니다. 일부 기업 고객은 방화벽에 고정 IP 주소를 등록해야만 접속할 수 있습니다. 어떤 로드 밸런서가 적합한가요?

UDP, 초당 수백만 요청, 고정 IP라는 세 키워드가 모두 NLB를 가리킵니다. NLB는 AZ마다 고정 IP를 쓰고 인터넷 경계일 때 서브넷당 Elastic IP 하나를 붙일 수 있습니다. ALB는 HTTP/HTTPS용이라 UDP를 받지 못하고 고정 IP도 없습니다.

Q3. 보안팀이 VPC로 들어오고 나가는 모든 트래픽을 서드파티 차세대 방화벽 어플라이언스 여러 대로 검사하려 합니다. 어플라이언스는 트래픽에 따라 확장되어야 하고, 한 대가 고장 나도 트래픽이 끊기지 않아야 합니다. 무엇을 써야 하나요?

서드파티 가상 어플라이언스(방화벽, IDS/IPS, 심층 패킷 검사)를 배포·확장하는 것이 GWLB의 존재 이유입니다. 라우팅 테이블에서 GWLB 엔드포인트를 다음 홉으로 지정합니다. AWS WAF는 HTTP 요청을 거르는 관리형 서비스로, "서드파티 어플라이언스"라는 요구와 맞지 않습니다.

Q4. NLB를 기본 설정으로 만들었습니다. AZ A에 대상 2대, AZ B에 대상 8대가 있고, DNS가 두 노드에 트래픽을 반씩 나눕니다. AZ A의 대상 한 대가 받는 트래픽은?

NLB는 교차 영역 로드 밸런싱이 기본 꺼짐입니다. AZ A 노드가 받은 50%를 AZ A의 2대가 나누므로 각 25%입니다. 10%는 교차 영역을 켰을 때(또는 ALB였을 때)의 값이고, 6.25%는 AZ B 대상 한 대의 몫입니다. 불균형이 문제라면 교차 영역을 켜면 됩니다.

Q5. ALB에서는 되지만 NLB에서는 되지 않는 것을 두 개 고르세요.

ALB 대상 유형은 instance, ip, lambda이고, 호스트 헤더 같은 요청 내용으로 라우팅합니다. NLB 대상은 인스턴스, IP, ALB입니다. Elastic IP 연결과 UDP는 거꾸로 NLB만 되는 기능입니다.

Q6. 오래된 웹 애플리케이션이 로그인 세션을 각 EC2 인스턴스의 메모리에 저장합니다. ALB 뒤로 옮기자 사용자가 요청마다 로그아웃되는 문제가 생겼습니다. 코드 변경 없이 가장 빨리 해결하는 방법은?

고정 세션은 쿠키로 같은 사용자의 요청을 같은 대상에 묶어 메모리 세션을 유지시킵니다. 등록 취소 지연은 대상을 빼는 순간의 진행 중 요청을, 느린 시작은 새 대상의 예열을 다루므로 이 증상과 무관합니다. 장기적으로는 세션 상태를 인스턴스 밖으로 빼는 설계가 확장에 유리하며, 이는 데이터베이스 레슨에서 다룹니다.

Q7. (복습 · 0010) 장애가 동시에 나면 안 되는 핵심 서버 6대를 한 AZ 안에서 서로 다른 하드웨어에 두려 합니다. 어떤 배치 그룹이 맞나요?

분산 배치 그룹은 인스턴스마다 서로 다른 하드웨어(랙)에 두며, AZ당 실행 인스턴스 7개까지라 6대는 들어갑니다. 클러스터는 오히려 가까이 모으고, 파티션이 하나뿐이면 그 안의 인스턴스는 랙을 공유할 수 있습니다.

Q8. ALB 대상 그룹의 EC2 인스턴스가 모두 unhealthy로 표시됩니다. 앱은 정상 동작하지만 / 경로가 로그인 페이지로 HTTP 302 리디렉션을 반환합니다. 상태 확인 설정은 기본값입니다. 올바른 조치는?

기본 성공 코드(Matcher)는 200, 기본 경로는 /입니다. 302는 실패로 판정됩니다. 200을 돌려주는 전용 경로(예: /health)로 바꾸거나 성공 코드에 302를 넣어야 합니다. 임계값을 올리면 실패 판정이 늦어질 뿐 결국 비정상이 됩니다.

기억에서 꺼내기

보지 말고 써 보세요. (1) ALB·NLB·GWLB의 계층, 대상 유형, 대표 키워드는? (2) 교차 영역 로드 밸런싱 기본값은 각각? (3) 등록 취소 지연과 고정 세션은 각각 어떤 문제를 푸나?

(1) ALB: 7계층, instance/ip/lambda, 경로·호스트 라우팅·WAF·인증. NLB: 4계층, 인스턴스/IP/ALB, 고정 IP·Elastic IP·UDP·초당 수백만 요청·소스 IP 보존. GWLB: 3계층, 가상 어플라이언스, GENEVE 6081·GWLB 엔드포인트·서드파티 방화벽.

(2) ALB는 로드 밸런서 수준에서 항상 켜짐(대상 그룹에서 끌 수 있음). NLB·GWLB는 기본 꺼짐.

(3) 등록 취소 지연: 대상을 뺄 때 진행 중 요청이 끝나길 기다림(기본 300초). 고정 세션: 쿠키로 사용자를 같은 대상에 묶어 인스턴스 메모리 세션을 유지.
