EC2 인스턴스 패밀리와 구매 옵션 완벽 정복

Amazon EC2 관련 시험 문제와 실무 아키텍처 설계의 절반은 "어떤 워크로드에 어떤 인스턴스 패밀리(유형)를 매칭할 것인가?"이고, 나머지 절반은 "그 인스턴스를 어떤 구매 옵션(Pricing Model)으로 조달하여 비용 효율성을 극대화할 것인가?"입니다. 이번 레슨에서는 복잡해 보이는 EC2 인스턴스 명명 규칙을 한눈에 해독하는 법부터, 워크로드별 인스턴스 패밀리(C, M, R, T, I 등), 핵심 구매 옵션(온디맨드, Savings Plans, 예약 인스턴스, 스팟, 전용 호스트, 용량 예약), 하드웨어 물리 배치를 결정하는 세 가지 배치 그룹, 그리고 메모리 상태를 보존하는 최대 절전(Hibernation)까지 원리부터 명쾌하게 정리합니다.

왜 EC2 인스턴스 패밀리와 구매 옵션을 배워야 할까요?

시험 관점: "가장 비용 효율적인(Most cost-effective) 아키텍처를 설계하라"는 유형의 단골 무대가 바로 EC2 구매 옵션입니다. 문제에 주어지는 워크로드의 특성(연중무휴 24/7 상시 운영, 단기적이고 예측 불가, 작업 중단 허용 여부, 특정 라이선스 준수 필요 등)만 보고 10초 안에 정확한 답을 도출할 수 있어야 합니다.
실무 관점: 완전히 동일한 vCPU와 메모리 스펙을 가진 가상 서버라도, 구매 옵션을 어떻게 조합하느냐에 따라 매달 청구서의 금액이 최대 70~90%까지 차이 납니다. 특히 1년이나 3년 장기 약정을 워크로드 성격에 맞지 않게 체결하면 되돌릴 수 없는 막대한 비용 손실이 발생하므로, 각 구매 옵션의 유연성과 제약 사항을 정확히 꿰뚫고 있어야 합니다.

EC2 인스턴스 명명 규칙: 이름만 보고 스펙 파악하기

EC2 인스턴스 이름은 복잡해 보이지만 규칙적인 조합으로 구성되어 있습니다. 예를 들어 c7gn.xlarge라는 인스턴스 유형은 인스턴스 패밀리(시리즈) c, 세대 번호 7, 추가 하드웨어 기능 속성 gn, 그리고 마침표 뒤의 인스턴스 크기 xlarge로 나뉩니다.[1] 핵심 글자들의 의미만 익혀두면 이름만 보고도 최적의 용도를 즉시 판별할 수 있습니다.

인스턴스 패밀리: 워크로드의 특성에 맞게 선택하기

애플리케이션 워크로드가 어떤 자원을 가장 많이 소모하느냐에 따라 적합한 인스턴스 패밀리가 결정됩니다.[2]

범주특화된 최적화 영역전형적인 워크로드 사례 (AWS 공식 가이드 기준)

T 시리즈의 핵심 원리: CPU 크레딧과 버스터블 성능

T 인스턴스(T3, T4g 등)는 평소에는 정해진 기본 CPU 성능(Baseline)을 제공하며, CPU 사용률이 기준치 아래로 내려가 한가할 때는 CPU 크레딧을 계정에 지속적으로 저축합니다. 그러다 웹 트래픽이 일시적으로 급증하면 저축해 둔 CPU 크레딧을 소모하면서 기준치를 훨씬 넘어 100%까지 자유롭게 버스트(Burst)하여 요청을 지연 없이 빠르게 처리합니다.[3] 따라서 평소에는 CPU 사용량이 낮고 간헐적으로 트래픽 스파이크가 발생하는 개발/테스트 환경, 사내 소규모 웹 사이트 등에 최적의 비용 효율성을 제공합니다.

EC2 구매 옵션: 무엇을 약속하고 어떤 할인을 얻을까?

EC2는 사용 패턴과 예산 계획에 따라 다양한 방식으로 구매할 수 있습니다.[4]

구매 옵션사용자가 약속하는 것얻는 혜택 및 핵심 제약 사항
온디맨드 (On-Demand)약정 없음 (언제든 생성/종료)초 단위 종량제 과금(최소 60초). 할인 없음. 단기적이고 불규칙하며 작업이 중간에 중단되어서는 안 되는 워크로드나 예측할 수 없는 신규 서비스에 권장[5]
Savings Plans1년 또는 3년 동안 시간당 일정 지출 금액(USD/시간) 약정[6]최대 66~72% 할인. AWS가 기존 예약 인스턴스(RI)보다 관리 편의성과 유연성이 뛰어나 공식적으로 가장 권장하는 약정 할인 방식[7]
예약 인스턴스 (RI)1년 또는 3년 동안 특정 인스턴스 사양 또는 리전 약정최대 72% 할인. 물리적 서버가 별도로 생기는 것이 아니라 청구서에서 사용량에 자동 적용되는 청구 할인 혜택. 결제는 전체 선결제, 부분 선결제, 선결제 없음 선택 가능[7]
스팟 인스턴스 (Spot)언제든 발생할 수 있는 인스턴스 중단을 감수함AWS 데이터 센터의 여유 유휴 컴퓨팅 용량을 온디맨드 대비 최대 90% 할인된 가격으로 이용[11]. AWS가 해당 용량을 필요로 할 때 회수되며, 회수 전 2분의 사전 경고 알림 제공[10]
전용 호스트 (Dedicated Hosts)물리적 블레이드 서버 한 대를 고객 전용으로 통째로 임대물리 서버의 소켓 수, 물리 코어 수에 대한 가시성 제공. 인스턴스가 항상 동일한 물리 호스트에 배치되도록 제어(호스트 선호도). 소켓/코어 단위 기존 소프트웨어 라이선스(BYOL) 준수에 필수[13]
전용 인스턴스 (Dedicated Instances)단일 고객 전용 격리 하드웨어에서 인스턴스 실행인스턴스 단위 과금. 다른 고객과 하드웨어를 공유하지 않는 물리적 격리만 제공하며, 소켓/코어 가시성이나 호스트 배치 제어는 지원되지 않음[13]
온디맨드 용량 예약 (ODCR)특정 가용 영역(AZ)의 물리적 용량 확보기간 약정 없이 특정 AZ의 용량을 물리적으로 100% 예약. 용량 예약 자체는 할인을 제공하지 않음(인스턴스를 켜지 않아도 온디맨드 요금 청구). 할인을 받으려면 Savings Plans나 리전 RI와 결합해야 함[14]

Savings Plans 두 종류 vs 예약 인스턴스(RI) 두 종류

시험에서 가장 헷갈리기 쉬운 약정 할인 상품들의 유연성과 제약 사항을 명확히 정리합니다.[6][7]

상품명변경 유연성 (적용 범위)최대 할인율 및 거래소 판매 여부
Compute Savings Plans최고의 유연성: 인스턴스 패밀리(C→M), 인스턴스 크기, 리전, OS, 테넌시가 바뀌어도 자동 할인. 심지어 AWS Fargate(서버리스 컨테이너)와 AWS Lambda 사용량까지 자동으로 포괄 적용최대 66% 할인[6]
EC2 Instance Savings Plans특정 리전의 특정 인스턴스 패밀리(예: 버지니아 북부의 m5)에 약정. 패밀리 내에서 인스턴스 크기, OS, 테넌시 변경은 자유로움최대 72% 할인 (패밀리가 고정되는 대신 더 높은 할인)[6]
Standard RI (표준 RI)패밀리 변경 불가. 가용 영역이나 크기 일부 수정(Modify)만 가능하며 타 패밀리로 교환 불가. 남는 약정은 RI Marketplace에서 타사에 판매 가능RI 상품 중 가장 높은 할인율[7]
Convertible RI (전환형 RI)계약 기간 중 다른 인스턴스 패밀리, 다른 OS, 다른 테넌시의 Convertible RI로 도중에 교환(Exchange) 가능 (단, 가치가 같거나 높아야 함). RI Marketplace 판매 불가[8][9]Standard RI보다 할인율이 다소 낮음

반드시 기억해야 할 시험 함정 두 가지:

  1. 스팟(Spot) 인스턴스는 Savings Plans 약정 적용 대상이 아닙니다. 스팟 사용 금액이 Compute Savings Plans 약정 시간을 채워주지 않습니다.[10]
  2. 용량을 물리적으로 보장(Capacity Guarantee)하는 옵션은 오직 '온디맨드 용량 예약(Capacity Reservation)'과 '영역(Zonal) RI'뿐입니다. 일반적인 리전 단위 RI나 Savings Plans는 오직 요금 할인 혜택만 제공할 뿐, 해당 리전이나 AZ에 물리적 인스턴스 자리가 남아있음을 보장하지 않습니다.[14]

스팟 인스턴스 중단 경고는 Amazon EventBridge 이벤트("EC2 Spot Instance Interruption Warning")와 인스턴스 메타데이터 서비스(IMDS)(spot/instance-action 경로)를 통해 인스턴스에 전달됩니다. 애플리케이션은 이 2분의 골든타임 동안 진행 중인 작업의 상태를 저장하고 안전하게 세션을 종료해야 합니다.[12]

EC2 배치 그룹 (Placement Groups): 인스턴스를 어디에 놓을 것인가?

배치 그룹은 여러 EC2 인스턴스가 물리적인 AWS 하드웨어 인프라 상에서 어떻게 배치될지를 제어하는 고급 구성 전략입니다.[15]

비교 항목클러스터 배치 그룹 (Cluster)분산 배치 그룹 (Spread)파티션 배치 그룹 (Partition)
배치 목표인스턴스들을 최대한 가까운 물리적 랙에 모아 극도의 초저지연 및 고대역폭 네트워크 통신 달성소수의 핵심 인스턴스들을 서로 다른 물리 랙(독립된 전원·네트워크)에 분산시켜 하드웨어 동시 장애 방지대규모 분산 시스템을 여러 논리적 파티션으로 나누고, 파티션마다 물리 랙을 분리하여 장애 도메인 격리
배치 범위 및 한계 수량단일 가용 영역(AZ) 내에서만 가능 (리전이나 다중 AZ 불가)다중 AZ 지원. 단, 가용 영역(AZ)당 실행 가능한 인스턴스가 최대 7개로 엄격히 제한됨다중 AZ 지원. AZ당 최대 7개 파티션 지원 (파티션 내부의 인스턴스 수는 계정 한도 내 수백 대 가능)
전형적인 사용 사례HPC(고성능 컴퓨팅), 긴밀히 연결된 노드 간 통신이 많은 과학 연산절대로 동시에 다운되면 안 되는 소수의 핵심 애플리케이션 인스턴스, DB 마스터/스탠바이HDFS(Hadoop), Apache Cassandra, Kafka 등 데이터 복제 위치를 인식하는 분산 빅데이터 시스템

EC2 최대 절전 모드 (Hibernation): 빠른 애플리케이션 재개

EC2 최대 절전(Hibernation) 모드는 인스턴스를 중지할 때 RAM(메모리)에 상주하던 운영체제 및 애플리케이션의 실행 상태를 그대로 EBS 루트 볼륨에 저장하고 전원을 끕니다. 나중에 인스턴스를 다시 시작하면, 부팅 및 초기화 과정을 처음부터 거치지 않고 EBS에 저장되어 있던 메모리 상태를 RAM으로 즉시 복원하여 이전 실행 상태 그대로 이어서 동작합니다. 인스턴스 ID, 프라이빗 IP 주소, Elastic IP 주소가 모두 그대로 유지됩니다.[16]

대규모 캐시를 메모리에 로드하거나 복잡한 애플리케이션 초기화(Warm-up)에 수십 분이 소요되는 워크로드를 빠르게 대기 상태로 유지하고 싶을 때 매우 유용합니다. 최대 절전 상태 동안에는 EC2 인스턴스 컴퓨팅 비용이 청구되지 않으며, RAM 내용을 포함한 EBS 볼륨 스토리지 요금만 발생합니다.[16]

최대 절전을 위한 필수 전제 조건 (시험 단골 체크리스트):[17]

  • 반드시 인스턴스를 처음 시작(Launch)할 때 최대 절전 옵션을 켜 두어야 합니다. 이미 실행 중이거나 중지된 기존 인스턴스에는 사후에 활성화할 수 없습니다.
  • 루트 볼륨은 임시 인스턴스 스토어가 아닌 EBS 볼륨이어야 하며, RAM에 있던 민감한 데이터가 디스크에 기록되므로 EBS 루트 볼륨이 반드시 암호화되어 있어야 합니다.
  • 인스턴스 RAM 크기 제한이 적용됩니다(대부분의 인스턴스 패밀리에서 지원되나 Linux 기준 150 GiB 미만 등). 온디맨드 및 스팟 인스턴스 모두 최대 절전을 지원합니다.

실전 연습 문제

학습한 내용을 바탕으로 문제를 풀어보세요. 보기 길이는 실제 시험처럼 균형 있게 구성되어 있습니다.

Q1. (시험형) 한 기업이 24시간 연중무휴 상시 운영되는 프로덕션 웹 애플리케이션 서버(현재 m5 패밀리 인스턴스 20대)의 향후 3년간 인프라 비용을 최소화하려 합니다. 클라우드 아키텍처 팀은 내년 상반기 중에 컴퓨팅 파워를 더 강화하기 위해 c 패밀리로 인스턴스 유형을 변경하거나, 일부 백엔드 서비스를 Amazon ECS on AWS Fargate 컨테이너로 점진적으로 마이그레이션할 계획을 갖고 있습니다. 이 기업에 가장 적합한 비용 최적화 구매 옵션은 무엇인가요?

Compute Savings Plans는 인스턴스 패밀리(m5 → c 패밀리), 인스턴스 크기, OS, 리전 변경에 전혀 구애받지 않고 유연하게 할인을 적용해 주며, 무엇보다 AWS Fargate와 Lambda 사용량까지 자동으로 포괄 할인해 줍니다. EC2 Instance Savings Plans는 할인은 약간 더 높지만 특정 패밀리(m5)에 고정되므로 패밀리 변경이나 Fargate 마이그레이션 시 할인을 받지 못합니다. Standard RI는 패밀리 교환이 아예 불가능합니다. 상시 프로덕션 환경을 스팟 인스턴스로만 구성하면 예고 없는 중단으로 서비스 장애가 발생할 수 있습니다.

Q2. (시험형) 매일 자정에 대용량 로그 데이터를 가공하고 집계하는 배치 처리 워크로드가 실행됩니다. 이 작업은 정기적으로 진행 상태를 S3에 체크포인트로 저장하도록 설계되어 있어 중간에 작업이 중단되더라도 중단된 지점부터 언제든 안전하게 재개할 수 있으며, 다음 날 아침 8시 업무 시작 전까지만 완료되면 충분합니다. 가장 비용 효율적인 EC2 구매 옵션은 무엇인가요?

"작업 중단 허용(내결함성)", "유연한 실행 시간대", "체크포인트 저장 가능"은 스팟 인스턴스(Spot Instances)를 선택하는 가장 완벽한 시나리오 조건입니다. 온디맨드 대비 최대 90% 저렴합니다. 매일 몇 시간만 실행되는 배치 작업에 3년 장기 약정(RI)을 체결하면 유휴 시간 동안 비용이 낭비되며, 전용 호스트는 기존 상용 라이선스 규정을 준수할 때 사용하는 고비용 옵션입니다.

Q3. (시험형) 항공기 날개 주변의 기류를 분석하는 복잡한 전산 유체 역학(CFD) 시뮬레이션 시스템을 수십 대의 고성능 EC2 인스턴스로 실행하려 합니다. 각 워커 노드들은 연산 과정에서 초당 수십 기가바이트의 중간 계산 데이터를 쉬지 않고 서로 주고받으므로, 노드 간 네트워크 지연 시간(Latency)이 전체 시뮬레이션 수행 시간을 결정합니다. 어떤 배치 그룹 전략을 사용해야 하나요?

클러스터 배치 그룹(Cluster Placement Group)은 단일 가용 영역(AZ) 내부에서 인스턴스들을 물리적으로 가장 가까운 동일 랙 및 네트워크 스위치에 밀집 배치함으로써 최저의 네트워크 지연 시간과 최대의 네트워크 처리량을 제공합니다. 분산(Spread) 및 파티션(Partition) 배치 그룹은 하드웨어 장애를 격리하기 위해 오히려 인스턴스를 물리적으로 멀리 떨어뜨려 놓으므로 네트워크 지연이 증가합니다.

Q4. (시험형) 한 빅데이터 팀이 수백 대 규모의 Apache Cassandra NoSQL 분산 데이터베이스 클러스터를 EC2 위에 구축하려 합니다. 특정 랙 하드웨어에 전원이나 네트워크 장애가 발생하더라도 데이터 복제본이 동시에 손실되지 않아야 하며, 카산드라 애플리케이션이 어떤 노드가 어느 물리적 랙에 배치되어 있는지 토폴로지를 직접 인식할 수 있어야 합니다. 가장 적합한 구성은 무엇인가요?

파티션 배치 그룹(Partition Placement Group)은 인스턴스 그룹을 여러 파티션으로 나누고 파티션마다 전용 물리 랙을 분리 배정합니다. 또한 인스턴스 메타데이터를 통해 각 인스턴스가 속한 파티션 번호를 노출하므로, Cassandra나 HDFS처럼 토폴로지를 인식하는 시스템이 데이터 복제본을 서로 다른 랙에 나누어 저장할 수 있습니다. 분산(Spread) 배치 그룹은 AZ당 실행 가능한 인스턴스가 최대 7개로 제한되므로 수백 대 규모의 대규모 클러스터에는 사용할 수 없습니다.

Q5. EC2 최대 절전(Hibernation) 기능을 성공적으로 사용하기 위한 필수 기술적 전제 조건으로 올바른 것을 두 개 고르세요.

최대 절전 모드는 RAM 메모리의 내용을 디스크에 기록하므로, 루트 볼륨은 영구적인 EBS 볼륨이어야 하며 메모리의 민감한 데이터 유출을 방지하기 위해 반드시 암호화되어 있어야 합니다. 또한 최대 절전 옵션은 인스턴스를 최초로 시작(Launch)하는 시점에만 활성화할 수 있으며, 이미 실행 중이거나 정지된 기존 인스턴스에 사후 설정할 수 없습니다.

Q6. (시험형) 한 금융 회사가 기존 온프레미스에서 물리 CPU 소켓 및 코어 단위로 라이선스 비용이 청구되는 상용 상용 데이터베이스 엔진을 AWS EC2로 마이그레이션하려 합니다. 소프트웨어 라이선스 준수 감사를 통과하기 위해 서버의 물리 소켓 수와 물리 코어 수를 명확히 확인할 수 있어야 하고, 인스턴스를 재부팅하더라도 항상 동일한 물리 하드웨어 서버에 계속 머무르도록 배치해야 합니다. 어떤 옵션을 선택해야 하나요?

전용 호스트(Dedicated Hosts)는 물리 서버 한 대를 고객 전용으로 통째로 할당하므로, 물리적 소켓과 코어 수에 대한 가시성을 제공하고 인스턴스를 특정 호스트에 고정 배치(호스트 선호도)할 수 있어 소켓/코어 단위 기존 라이선스(BYOL) 준수에 필수적입니다. 전용 인스턴스(Dedicated Instances)도 물리적으로 격리된 전용 하드웨어에서 실행되지만, 소켓/코어 가시성이 없고 인스턴스 재부팅 시 다른 물리 서버로 이동할 수 있어 라이선스 감사 요건을 충족하지 못합니다.

Q7. (0002 복습 연계) EC2 인스턴스에서 구동되는 웹 애플리케이션이 동일한 계정 내의 Amazon DynamoDB 테이블에 데이터를 읽고 써야 합니다. AWS 보안 모범 사례에 부합하는 가장 안전하고 올바른 자격 증명 관리 아키텍처는 무엇인가요?

레슨 0002에서 다루었듯이, EC2 워크로드가 AWS 리소스와 통신할 때는 인스턴스 프로파일(Instance Profile)을 통해 IAM 역할을 연결하는 것이 모범 사례입니다. 인스턴스 메타데이터 서비스(IMDS)를 통해 자동으로 교체되는 임시 보안 자격 증명을 사용할 수 있습니다. 장기 액세스 키를 사용자 데이터(User Data) 스크립트나 커스텀 AMI 이미지에 하드코딩하는 것은 유출 위험이 매우 큰 안티 패턴이며, 루트 자격 증명은 절대 사용해서는 안 됩니다.

Q8. (시험형) 다음 주에 이틀 동안 진행되는 전국 단위 온라인 콘서트 티켓 예매 이벤트를 위해 특정 가용 영역(AZ)에서 최신 컴퓨팅 인스턴스(c7i.4xlarge) 50대를 용량 부족 오류(InsufficientInstanceCapacity) 없이 확실하게 시작할 수 있어야 합니다. 회사는 이틀간의 이벤트가 끝나면 즉시 자원을 반납하길 원하며 1년 이상의 장기 약정은 체결하고 싶지 않습니다. 가장 적합한 옵션은 무엇인가요?

온디맨드 용량 예약(On-Demand Capacity Reservations)은 특정 가용 영역(AZ)에 원하는 인스턴스 용량을 100% 물리적으로 확보해 주며, 기간 약정이 없어 이벤트가 끝난 뒤 즉시 예약을 취소(해제)할 수 있습니다. Savings Plans와 리전 단위 RI는 청구 할인만 제공할 뿐 용량 확보를 보장하지 않으며 둘 다 1년 이상의 장기 약정입니다. 스팟 인스턴스는 피크 시간대에 여유 용량이 부족하면 시작되지 않거나 실행 도중 회수될 수 있습니다.

(3) 세 가지 배치 그룹(클러스터, 분산, 파티션)의 핵심 목표와 가용 영역당 제약 숫자(한계 수량)는 각각 무엇인가요?

(1) 작업 중단 허용(배치·빅데이터) → 스팟 인스턴스(Spot) (최대 90% 할인). 상시 프로덕션(1~3년) → Savings Plans / RI (특정 AZ 용량 보장 필요 시 '용량 예약' 결합). 단기·불규칙·중단 불가 → 온디맨드(On-Demand).
(2) Compute SP: 패밀리·크기·리전·OS 무관 + Fargate·Lambda 포괄 적용(최대 66% 할인). EC2 Instance SP: 특정 리전의 특정 패밀리에 고정, 크기·OS 변경 가능(최대 72% 할인). Standard RI: 패밀리 교환 불가, Marketplace 타사 판매 가능. Convertible RI: 다른 패밀리로 도중 교환 가능, 판매 불가. (AWS는 RI보다 관리가 쉬운 Savings Plans를 공식 권장).
(3) 클러스터: 단일 AZ 전용, 초저지연·고대역폭(HPC). 분산: 서로 다른 물리 랙에 분산, AZ당 실행 인스턴스 최대 7개 제한. 파티션: 랙 분리 파티션, AZ당 최대 7개 파티션 지원(파티션당 인스턴스 수는 무제한, Cassandra/HDFS용).

추가 학습 및 실습

콘솔 실습 (선택 사항, 비용 0원): AWS 콘솔의 EC2 메뉴에서 인스턴스 유형(Instance Types)을 열고 속성 필터에 On-Demand Hibernation support = true를 설정하여 최대 절전을 지원하는 인스턴스 목록을 둘러보세요. 또한 스팟 요청(Spot Requests) → 가격 내역(Pricing history) 화면에서 동일한 인스턴스 유형이라도 가용 영역(AZ)마다 스팟 할인율이 실시간으로 어떻게 다른지 확인해 보세요. 인스턴스를 직접 시작하지 않는 한 요금은 전혀 발생하지 않습니다.
