온프레미스와 AWS 잇기:
Storage Gateway, DataSync, Transfer Family, 오프라인 전송

하이브리드 아키텍처 문제는 결국 "기존 온프레미스 인프라와 AWS 클라우드를 어떻게 연결할 것인가"로 귀결됩니다. 핵심 판단 기준은 명확합니다. 온프레미스 앱이 클라우드 스토리지를 실시간으로 계속 함께 쓰는가(Storage Gateway), 대용량 데이터를 한 번에 옮기거나 주기적으로 동기화하는가(DataSync / 오프라인 물리 전송), 아니면 외부 협력사나 고객이 기존 SFTP 같은 프로토콜로 직접 파일을 전송하는가(Transfer Family). 여기에 네트워크 대역폭과 일정을 계산하여 온라인과 오프라인을 가르는 확실한 공식까지 상세히 정리합니다.

왜 하이브리드 스토리지와 전송 서비스를 배워야 할까요?

시험에서: "온프레미스 레거시 애플리케이션이 NFS 프로토콜로 S3를 마운트하여 사용해야 한다", "기존 백업 절차와 테이프 소프트웨어 변경 없이 물리 테이프를 제거하고 싶다", "100TB의 데이터를 일주일 안에 이전해야 한다" 같은 문제가 나오면 이번 레슨에서 다루는 서비스 중 하나가 무조건 정답입니다.
실무에서: 클라우드 마이그레이션 계획을 수립할 때 엔지니어가 가장 먼저 맞닥뜨리는 질문이 바로 "현재 보유한 전용선이나 인터넷 회선으로 며칠 만에 데이터를 다 보낼 수 있는가?"입니다. 대역폭과 전송 기간을 계산하지 못하면 전체 프로젝트 일정이 통째로 어그러집니다.

Storage Gateway: 온프레미스에서 계속 쓰는 클라우드 스토리지

온프레미스의 레거시 애플리케이션은 S3의 REST API를 직접 호출하도록 코드를 수정하기 어려운 경우가 많습니다. 대신 기존에 쓰던 파일(NFS/SMB), 블록(iSCSI), 백업 테이프(VTL) 프로토콜을 그대로 쓰길 원합니다. AWS Storage Gateway는 온프레미스 가상 머신(VMware ESXi, Hyper-V, KVM, Nutanix AHV)이나 전용 하드웨어 어플라이언스에 소프트웨어를 배포하여, 표준 스토리지 프로토콜 인터페이스를 제공하면서 실제 데이터는 AWS 클라우드(S3, Glacier, EBS 스냅샷)에 안전하게 저장해 주는 하이브리드 스토리지 서비스입니다.[1]

Volume Gateway 심층 분석: 캐시형(Cached) vs 저장형(Stored)

시험에서 가장 빈번하게 출제되는 함정 포인트 중 하나입니다. 두 방식 모두 iSCSI 블록 인터페이스를 쓰지만, 데이터의 기본 거주 위치가 정반대입니다.[1]

  • 캐시형 볼륨 (Cached Volumes): 기본 주 데이터 저장소는 Amazon S3입니다. 온프레미스 로컬 스토리지에는 최근 자주 접근하는 활성 데이터만 캐싱해 둡니다. 따라서 온프레미스의 비싼 고성능 스토리지를 대규모로 증설할 필요 없이, 클라우드의 무제한 용량을 마치 로컬 디스크처럼 경제적으로 활용하고 싶을 때 선택합니다.
  • 저장형 볼륨 (Stored Volumes): 전체 원본 데이터셋을 온프레미스 로컬 스토리지에 전부 보관합니다. 따라서 모든 데이터에 대해 온프레미스 로컬 디스크의 극도로 낮은 지연 시간(Low Latency)으로 접근해야 하는 까다로운 워크로드에 사용됩니다. AWS S3는 어디까지나 백업용 보조 저장소로 동작하며, 시점별 비동기 스냅샷(EBS 스냅샷)을 만들어 클라우드에 오프사이트 백업을 안전하게 보관합니다.

DataSync: 온라인으로 빠르고 안전하게 옮기고 동기화하기

AWS DataSync는 온프레미스 스토리지와 AWS 클라우드 스토리지 사이, 혹은 서로 다른 클라우드/AWS 서비스 간에 대규모 데이터를 고속으로 이동하고 동기화해 주는 완전관리형 온라인 데이터 전송 서비스입니다.[5]

  • 지원 소스 및 타깃: 온프레미스의 NFS, SMB, HDFS, 객체 스토리지와 AWS의 Amazon S3, Amazon EFS, Amazon FSx 4종(Windows, Lustre, ONTAP, OpenZFS) 간 양방향 전송을 완벽히 지원합니다. 심지어 Google Cloud Storage나 Azure Blob 같은 타사 퍼블릭 클라우드 스토리지에서 AWS로 데이터를 가져올 때도 사용할 수 있습니다.[5]
  • 전송 아키텍처 및 에이전트: 온프레미스 스토리지와 통신할 때는 온프레미스 가상 머신에 전용 DataSync 에이전트(Agent)를 배포하여 스토리지를 읽고 씁니다. 반면, 같은 AWS 계정 및 리전 내부의 AWS 스토리지 서비스끼리 데이터를 이동할 때는(예: S3에서 EFS로) 별도의 에이전트 설치가 전혀 필요 없으며 모든 트래픽이 안전한 AWS 전용 백본 네트워크 내부에서만 처리됩니다.[6]
  • 안전성과 자동화: 전송 구간 전체에서 TLS 암호화를 적용하며, 전송 중 및 전송 완료 후 데이터 무결성 검증(Checksum 검사)을 자동으로 수행합니다. 또한 작업 예약(Scheduling), 변경된 파일만 골라 보내는 증분 동기화, 업무 시간 동안 회선을 독점하지 않도록 하는 대역폭 제한(Bandwidth Throttling) 옵션을 제공하므로 주기적인 백업 및 동기화 작업에 최적입니다.[6]
  • 주요 활용 사례: 대규모 활성 데이터셋 마이그레이션, 콜드 데이터를 S3 Glacier Flexible Retrieval 또는 Deep Archive로 즉시 전송하여 아카이브, EFS 또는 FSx 대기 파일 시스템으로의 주기적 재해 복구(DR) 복제 등.[5]

Storage Gateway vs DataSync: 헷갈리지 않는 명확한 구별법

두 서비스의 본질적인 차이를 기억하세요. Storage Gateway는 온프레미스 애플리케이션이 클라우드 스토리지를 지속적으로 마운트하여 실시간으로 함께 쓰도록 해 주는 '하이브리드 스토리지 연결 다리'입니다. 반면 DataSync는 데이터를 한곳에서 다른 곳으로 고속 전송하고 마이그레이션하거나 주기적으로 동기화하는 '데이터 이동 도구'입니다. AWS 공식 아키텍처 가이드에서도 DataSync는 '온라인 마이그레이션 도구'로, File Gateway는 '하이브리드 스토리지 저장 도구'로 엄밀히 구분하고 있습니다.[7]

Transfer Family: 외부 파트너의 SFTP 환경을 그대로 수용하기

기업 환경에서는 수백 군데의 외부 협력사나 고객사가 매일 정해진 시간에 SFTP로 주문서나 정산 파일을 전송하는 경우가 흔합니다. 이때 협력사들에게 "앞으로는 S3 API를 쓰세요"라고 요구하는 것은 현실적으로 불가능합니다.
AWS Transfer Family는 SFTP, FTPS, FTP, AS2 프로토콜과 최신 웹 브라우저 기반 전송을 완전관리형 엔드포인트로 제공합니다. 외부 파트너가 업로드한 데이터는 백엔드의 Amazon S3 또는 Amazon EFS에 객체 및 파일 형태로 곧바로 저장됩니다.[8]

서버 인프라나 패치를 관리할 필요가 전혀 없으며, 파트너사가 기존에 쓰던 클라이언트 설정(SSH 키 인증, 방화벽 IP 허용 등)을 단 하나도 변경하지 않고 엔드포인트 도메인 이름(CNAME)만 연결하면 됩니다. 최대 3개 가용 영역(AZ)에 걸친 자동 이중화 구성으로 뛰어난 고가용성을 보장합니다.[8]

온라인이냐 오프라인이냐: 대역폭과 이전 일정의 수학적 기준

데이터 마이그레이션에서 온라인(네트워크 회선)과 오프라인(물리 장치 배송)을 결정하는 기준은 크게 두 가지입니다.[7]

  1. 소요 시간과 긴급성: 온라인 전송은 즉시 시작할 수 있어 분~시간 단위로 데이터가 계속 흐르지만, 오프라인 장비 배송은 장비를 신청하고 배송받아 복사하고 반송하는 물리적 물류 기간(보통 1~2주)이 기본적으로 소요됩니다.
  2. 네트워크 대역폭 한계와 업무 영향: 네트워크 회선이 좁은데 옮겨야 할 데이터가 수백 테라바이트에 달한다면 수개월에서 수년이 걸릴 수 있습니다. 또한 온라인 전송이 사내 업무용 인터넷 대역폭을 잠식하면 정상적인 업무가 불가능해집니다. 따라서 네트워크 대역폭이 부족하고 정해진 기한이 촉박하다면 오프라인 물리 전송이 유일한 해법이 됩니다.

대역폭 계산의 기본 공식 (이것 하나만 외우면 끝납니다)

네트워크 속도는 bps(초당 비트)이고 파일 크기는 Byte(바이트, 1 Byte = 8 bits)입니다.
따라서 1 Gbps = 1,000 Mbps = 125 MB/s입니다. 하루는 86,400초(60초 × 60분 × 24시간)이므로, 회선을 24시간 내내 100% 한계치까지 가동한다고 가정해도 전송량은 다음과 같습니다:
1 Gbps 회선 100% 가동 시 하루 최대 전송량 ≈ 125 MB/s × 86,400초 ≈ 10,800,000 MB ≈ 약 10.8 TB / 일

이전 대상 데이터 크기100 Mbps 회선 (하루 약 1.08 TB)1 Gbps 회선 (하루 약 10.8 TB)10 Gbps 회선 (하루 약 108 TB)
10 TB약 9 ~ 10일 소요약 1일 소요약 2 ~ 3시간 소요
100 TB약 93일 (3개월 이상)약 9 ~ 10일 소요약 1일 소요
1 PB (1,000 TB)약 926일 (약 2.5년)약 93일 (약 3개월)약 9 ~ 10일 소요

※ 위 표는 회선 점유율 100%를 가정한 이론적 수치입니다. 실제 환경에서는 프로토콜 오버헤드와 사내 업무 트래픽을 고려하여 50~70% 수준으로 계산해야 하므로 실제 기간은 훨씬 더 길어집니다.

오프라인 물리 전송: AWS Snow Family와 최신 동향

시험 문제와 실무에서 "네트워크 대역폭이 턱없이 부족한 상황에서 수십~수백 TB의 대용량 데이터를 정해진 기한 내에 1회성으로 이전해야 한다"는 시나리오의 표준 정답은 AWS Snowball Edge(보안 하드웨어 어플라이언스를 택배로 배송받아 로컬 네트워크에서 데이터를 복사한 후 AWS 데이터센터로 반송하는 물리 전송)입니다.
Snow 패밀리의 장치 라인업은 다음과 같습니다:

  • AWS Snowcone: 가장 작고 가벼운 휴대용 엣지 컴퓨팅 및 데이터 전송 장치(약 2.1kg, 8TB~14TB 용량). 배터리 구동이 가능하여 IoT 센서 현장이나 드론 등 열악한 환경에서 데이터를 수집하고 EC2 컴퓨팅을 실행할 수 있습니다.
  • AWS Snowball Edge: 여행 가방 크기의 견고한 엔터프라이즈 장비로, 대용량 스토리지 이전(Storage Optimized: 가용 약 80TB~210TB)과 현장 엣지 연산(Compute Optimized)을 지원합니다. 기기 외부에 전자잉크(E-ink) 배송 라벨이 부착되어 있고, 256비트 하드웨어 암호화(KMS)와 최대 100 Gbps 고속 네트워크 어댑터를 갖추고 있습니다.[9]
  • AWS Snowmobile: 최대 100PB를 수송하던 45피트 대형 트럭 컨테이너였으나, 현재는 공식적으로 서비스가 종료되었습니다.

최신 현업 상태와 SAA-C03 시험 전략:

  • AWS 공식 문서상 Snowball Edge는 신규 상용 고객에게 점진적으로 제공이 제한되고 있으며, AWS는 온라인 전송의 경우 DataSync, 물리적 직접 반입의 경우 AWS Data Transfer Terminal 또는 공인 마이그레이션 파트너 솔루션을 권장하고 있습니다.[9][7]
  • AWS Data Transfer Terminal: 고객이 예약된 AWS 물리 시설(Terminal)에 자체 대용량 하드 드라이브를 직접 들고 가 초고속 인터페이스로 S3 버킷 등에 고속 주입하는 신규 엔터프라이즈 솔루션입니다.[10]
  • 수험 대비 핵심: SAA-C03 시험의 문제 은행은 이러한 서비스 정책 변경보다 보수적으로 출제됩니다. 시험 문제에서 "네트워크 대역폭 제약 + 수십~수백 TB 대용량 + 수일~수주 내 이전 기한" 조건이 나오면 고민하지 말고 보기 중에서 Snowball Edge (또는 오프라인 물리 전송)를 정답으로 선택하세요!

시험에 자주 나오는 핵심 패턴

온프레미스 레거시 앱이 NFS/SMB 파일 공유로 S3 사용, 로컬 저지연 캐시 필요 → S3 File Gateway
iSCSI 가상 하드디스크 제공, 로컬 스토리지 확장을 최소화하고 자주 쓰는 데이터만 캐싱 → Volume Gateway 캐시형
전체 데이터를 온프레미스에 보관하여 저지연 보장, 클라우드에는 비동기 EBS 스냅샷 백업 → Volume Gateway 저장형
기존 백업 소프트웨어/VTL 프로세스 유지, 물리 테이프 인프라 제거, 저렴한 장기 아카이브 → Tape Gateway
온프레미스 NFS/SMB/HDFS를 S3·EFS·FSx로 고속 마이그레이션, 무결성 검증, 스케줄링 → AWS DataSync
외부 거래처가 기존 SFTP/FTPS 클라이언트로 파일 전송, 서버 관리 오버헤드 제거, S3 저장 → AWS Transfer Family
네트워크 회선 대역폭으로 계산했을 때 기한 내 온라인 전송 불가능 → 오프라인 물리 전송 (Snowball Edge)
지속적이고 안정적인 초저지연 하이브리드 전용망 연결 → AWS Direct Connect

연습

실제 시험이라고 생각하고 풀어보세요. 먼저 시나리오가 "온프레미스에서 클라우드 스토리지를 실시간으로 계속 쓰는가", "데이터를 완전히 마이그레이션하는가", "외부 파트너의 파일 전송인가"를 먼저 파악하고, 전송 문제라면 대역폭 계산부터 진행하세요.

Q1. 온프레미스의 빅데이터 분석 서버들이 NFS 프로토콜을 사용해 대용량 로그 파일을 작성하고 있으며, 현재 온프레미스 스토리지 용량이 거의 포화 상태입니다. 로그 파일을 Amazon S3에 개별 객체로 저장하여 S3 수명 주기 정책을 적용해야 하며, 가장 최근 로그 파일은 온프레미스 분석 서버에서 지연 시간 없이 빠르게 읽을 수 있어야 합니다. 가장 적합한 아키텍처는 무엇입니까?

정답은 S3 File Gateway입니다! 문제의 핵심 키워드는 'NFS 프로토콜 사용', 'S3 버킷에 객체로 저장하여 수명 주기 정책 활용', '최근 파일에 대한 로컬 캐시 저지연 접근'입니다. S3 File Gateway는 온프레미스 서버에 NFS/SMB 마운트를 제공하고, 파일 하나를 S3 객체 하나로 직접 1:1 저장하므로 S3 수명 주기 정책을 완벽히 적용할 수 있습니다. 반면 Volume Gateway는 iSCSI 블록 장치이므로 파일이 개별 S3 객체로 노출되지 않으며, DataSync는 전송 작업일 뿐 온프레미스 서버가 실시간으로 마운트하여 계속 쓸 수 있는 파일 공유 스토리지를 제공하지 못합니다.

Q2. 한 금융 회사가 데이터센터에서 사용 중인 물리적 테이프 라이브러리 장비와 값비싼 오프사이트 테이프 보관 계약을 완전히 없애려 합니다. 하지만 기존에 엔지니어들이 사용하던 백업 소프트웨어와 운영 절차는 그대로 유지해야 하며, 생성된 백업 데이터는 규정 준수를 위해 장기간 가장 저렴한 비용으로 보관되어야 합니다. 어떤 서비스를 도입해야 합니까?

정답은 Tape Gateway입니다! 기존 백업 소프트웨어(Veeam, Commvault, Veritas 등)의 설정을 변경하지 않고 그대로 테이프 백업 명령을 내릴 수 있는 가상 테이프 라이브러리(VTL) 인터페이스를 제공하는 유일한 서비스입니다. Tape Gateway가 생성한 가상 테이프는 S3 Glacier Flexible Retrieval 및 Deep Archive로 자동 보관되어 업계 최저 수준의 비용으로 규정 준수 장기 보관을 실현합니다. File Gateway나 Transfer Family를 쓰면 백업 소프트웨어의 작업 방식을 파일 복사 스크립트 등으로 전면 개편해야 하므로 문제의 조건에 위배됩니다.

Q3. 한 기업이 온프레미스 NAS(NFS)에 보관된 40TB 규모의 업무 문서를 Amazon EFS 파일 시스템으로 이전하려 합니다. 회사는 온프레미스와 AWS 간에 10 Gbps AWS Direct Connect 전용선을 보유하고 있습니다. 마이그레이션 작업 후 데이터 무결성을 검증하고, 서비스 전환(Cutover) 직전까지 변경된 최신 파일만 지속적으로 자동 동기화하고자 합니다. 관리 오버헤드가 가장 적은 최적의 솔루션은 무엇입니까?

정답은 AWS DataSync 에이전트와 예약된 전송 작업입니다! 10 Gbps 전용선이면 이론상 하루에 약 108TB를 전송할 수 있으므로, 40TB는 반나절~하루 이내에 온라인으로 충분히 전송할 수 있습니다. DataSync는 온프레미스 NFS에서 Amazon EFS로의 직접 전송을 완벽히 지원하며, 체크섬 기반 데이터 무결성 자동 검증, 변경된 파일만 전송하는 증분 동기화, 정기 스케줄링 기능이 모두 완전관리형으로 내장되어 있어 rsync 스크립트처럼 서버를 직접 관리할 필요가 전혀 없습니다.

Q4. 한 전자상거래 플랫폼에서 200여 개 외부 협력사가 매일 밤 정해진 시간에 SFTP를 통해 주문 및 재고 CSV 파일을 전송하고 있습니다. 협력사 측의 기존 SFTP 클라이언트 설정이나 인증 방식을 전혀 변경하지 않으면서, 회사는 자체 SFTP 서버 호스팅 및 관리 부담을 완전히 없애고 수신된 파일을 Amazon S3 버킷에 직접 수집하고자 합니다. 가장 적합한 구성은 무엇입니까?

정답은 AWS Transfer Family의 SFTP 엔드포인트 + S3입니다! Transfer Family는 서버 관리 없이 완전관리형 SFTP 엔드포인트를 제공하며, 데이터는 S3 버킷에 직접 저장됩니다. 협력사들은 기존에 사용하던 SFTP 클라이언트 프로그램과 자격 증명을 그대로 사용하면서 호스트 주소만 연결하면 됩니다. EC2에 직접 SFTP를 구성하는 것은 서버 관리 및 패치 오버헤드가 크며, 200개 파트너사에 File Gateway나 DataSync 에이전트를 설치하게 하는 것은 외부 파트너 환경을 변경하지 않는다는 조건에 완전히 위배됩니다.

Q5. 산간 지역에 위치한 연구소에서 수집된 500TB의 기상 관측 데이터를 3주 안에 Amazon S3로 이전해야 합니다. 해당 연구소의 유일한 외부 네트워크는 100 Mbps 공용 인터넷 회선이며, 연구원들의 일상 업무에도 반드시 사용되어야 합니다. 기한 내에 가장 안전하고 확실하게 데이터를 이전하는 방법은 무엇입니까?

정답은 AWS Snowball Edge 등 물리 저장 장치를 이용한 오프라인 전송입니다! 대역폭 계산 공식을 적용해 보세요. 100 Mbps 회선은 24시간 100% 가동해도 하루에 전송 가능한 최대 데이터양이 약 1.08TB에 불과합니다. 따라서 500TB를 모두 전송하려면 최소 460일(1년 3개월 이상)이 걸립니다. 일상 업무 트래픽까지 고려하면 기한인 3주 내 전송은 네트워크상 물리적으로 절대 불가능합니다. S3 Transfer Acceleration은 라우팅 경로를 최적화할 뿐 로컬 인터넷 대역폭 한계(100 Mbps)를 늘려주지 못합니다. 따라서 물리 장비를 배송받아 로컬 네트워크에서 고속 복사 후 반송하는 오프라인 물리 전송만이 유일한 해법입니다.

Q6. AWS Storage Gateway의 Volume Gateway 구성에 대한 설명으로 옳은 것 두 가지를 고르세요.

정답은 첫 번째(캐시형 특징)와 네 번째(저장형 특징)입니다!
캐시형 볼륨(Cached Volumes)은 실제 기본 저장소가 클라우드의 S3이며, 온프레미스에는 자주 읽고 쓰는 데이터만 캐싱하여 로컬 디스크 증설 비용을 최소화합니다. 반대로 저장형 볼륨(Stored Volumes)은 전체 원본 데이터를 온프레미스 로컬 스토리지에 유지하여 극도로 낮은 저지연을 보장하고, 시점별 비동기 스냅샷(EBS 스냅샷 형태)을 S3에 오프사이트 백업으로 저장합니다. 두 방식 모두 파일 공유(NFS)가 아니라 iSCSI 블록 볼륨 인터페이스를 제공합니다.

Q7. (0018 복습) 한 기업이 온프레미스 파일 서버에 있는 수년간 보관된 과거 프로젝트 문서 80TB를 AWS DataSync를 통해 Amazon S3로 직접 아카이브하고자 합니다. 이 데이터는 법적 감사가 발생할 때만 드물게 열람하며(1년에 한 번 이하), 파일 복원 요청 후 최대 48시간 이내에만 데이터를 검색할 수 있으면 충분합니다. 스토리지 보관 비용을 가장 절감할 수 있는 S3 스토리지 클래스는 무엇입니까?

정답은 Amazon S3 Glacier Deep Archive입니다! AWS DataSync는 온프레미스 파일 데이터를 S3 Standard뿐만 아니라 S3 Glacier Flexible Retrieval이나 Glacier Deep Archive 스토리지 클래스로 중간 변환 과정 없이 직접 전송할 수 있습니다. 1년에 1회 미만 접근하고 48시간 이내 복원 허용이라는 조건은 Glacier Deep Archive(벌크 복구 시 48시간 이내, GB당 월 $0.00099 수준으로 업계 최저가)에 완벽히 부합합니다.

Q8. (0007·0019 복습) 온프레미스 데이터센터에서 실행 중인 Linux 배치 분석 서버들이 피크 시간대 클라우드 버스팅(Cloud Bursting)을 위해 AWS VPC에 생성된 Amazon EFS 파일 시스템을 직접 마운트하여 대용량 파일을 읽고 쓰려 합니다. 이 아키텍처를 구현하기 위해 반드시 갖추어야 하는 필수 네트워크 구성 요소는 무엇입니까?

정답은 Direct Connect 또는 Site-to-Site VPN 전용 연결입니다! Amazon EFS는 프라이빗 VPC 내부의 서브넷에 생성된 마운트 타깃(Mount Target, 사설 IP)을 통해 접근합니다. EFS는 절대로 공용 인터넷으로 엔드포인트를 노출할 수 없으므로, 온프레미스 서버에서 EFS를 직접 NFS 마운트하려면 온프레미스와 VPC가 Direct Connect나 IPSec VPN으로 프라이빗하게 연결되어 있어야 합니다.[11] FSx File Gateway는 Windows SMB용이며 EFS 마운트와는 무관합니다.

학습 내용 되짚어보기 (인출 연습)

교재를 보지 말고 머릿속 기억만으로 정리해 보세요.
(1) Storage Gateway의 네 가지 유형(S3 File, FSx File, Volume, Tape)이 제공하는 프로토콜 인터페이스와 실제 데이터가 저장되는 AWS 위치는 각각 어디인가요?
(2) Storage Gateway, DataSync, Transfer Family 세 서비스의 결정적인 차이점을 한 문장씩 설명해 보세요.
(3) 100 Mbps 회선과 1 Gbps 회선의 하루 이론상 최대 데이터 전송량은 각각 얼마이며, 100TB를 1 Gbps 회선으로 온전히 이전하려면 대략 며칠이 소요될까요?

(1) Storage Gateway 4가지 유형:
- S3 File Gateway: NFS/SMB 파일 공유 인터페이스 제공 → 로컬 캐시를 거쳐 S3 버킷에 1:1 객체로 저장.
- FSx File Gateway: SMB 파일 공유 제공 → FSx for Windows File Server에 저장 (신규 고객 제공 중단).
- Volume Gateway: iSCSI 블록 스토리지 제공 → 캐시형은 S3가 기본 저장소이고 자주 쓰는 것만 로컬 캐싱, 저장형은 전체 데이터가 로컬에 있고 시점 비동기 EBS 스냅샷을 S3에 백업.
- Tape Gateway: 가상 테이프 라이브러리(VTL, iSCSI) 인터페이스 제공 → S3 Glacier Flexible Retrieval 및 Deep Archive에 가상 테이프 아카이브.

(2) 세 서비스의 명쾌한 1문장 구별:
- Storage Gateway: 온프레미스 애플리케이션이 클라우드 스토리지를 실시간으로 '계속 함께 사용'하기 위한 하이브리드 연결 다리.
- DataSync: 온프레미스와 AWS 간에 대규모 활성 데이터를 초고속으로 '이전하거나 주기적으로 동기화'하는 완전관리형 데이터 마이그레이션 도구.
- Transfer Family: 외부 거래처의 기존 SFTP/FTPS/FTP/AS2 전송 환경을 수정 없이 그대로 수용하여 'S3 또는 EFS에 바로 저장'해 주는 완전관리형 서버리스 엔드포인트.

(3) 대역폭 및 일정 계산:
- 100 Mbps 회선: 하루 최대 약 1.08 TB 전송 가능.
- 1 Gbps 회선: 하루 최대 약 10.8 TB 전송 가능 (125 MB/s × 86,400초).
- 100 TB를 1 Gbps 회선으로 이전 시: 100 TB ÷ 10.8 TB/일 ≈ 약 9~10일 소요 (회선 100% 점유 가정 시).

추가 학습 및 실습

1차 공식 문서 정독 (10분 투자): AWS 공식 의사결정 가이드 "Choosing an AWS storage service" 문서의 Migration options 및 Choose 비교 표를 꼭 확인하세요. 온라인 전송과 오프라인 물리 전송을 선택하는 기준과 Snow 패밀리의 최신 정책이 매우 명쾌하게 정리되어 있습니다.

실습 가이드 (비용 최소화 실습): AWS DataSync 콘솔에 들어가 같은 리전 내 서로 다른 S3 버킷 두 개를 생성하고 전송 태스크를 생성해 보세요. AWS 리소스 간 전송이므로 별도의 에이전트 설치 없이 몇 번의 클릭만으로 전송 작업을 정의할 수 있습니다. 1~2개의 작은 테스트 파일만 동기화해 보고, DataSync는 전송된 데이터 기가바이트당 과금되므로 테스트 후 즉시 작업(Task)과 버킷을 삭제하여 불필요한 비용을 방지하세요.

궁금한 점이 있으신가요?

퀴즈 점수와 틀린 문항을 확인해 보세요. 특히 Q5의 대역폭 계산 공식이나 Volume Gateway의 캐시형/저장형 구분 기준이 헷갈리신다면 주저 없이 질문해 주세요. 다음 레슨(0021)에서는 데이터베이스의 핵심인 RDS Multi-AZ와 Aurora 아키텍처를 집중적으로 탐구합니다!
