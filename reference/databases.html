RDS 가용성과 확장 (0021)

Multi-AZ DB 인스턴스Multi-AZ DB 클러스터읽기 전용 복제본
목적고가용성고가용성 + 읽기읽기 확장, DR
복제동기식반동기식비동기식
대기에서 읽기불가리더 2개 가능가능
범위같은 리전 다른 AZAZ 3곳다른 리전 가능
장애 시자동, DNS 전환, 보통 60–120초자동수동 승격
  • RDS Proxy: 연결 풀링. Lambda, "too many connections", 장애 조치 시간 최대 66% 단축, Secrets Manager/IAM 인증. 같은 VPC, 퍼블릭 불가.
  • 백업: 자동 백업 보존 0–35일(PITR). 그 이상 또는 인스턴스 삭제 후에도 보관 → 수동 스냅샷.
  • 스토리지 자동 확장: 여유 10% 이하 5분 지속 시 최대 임곗값까지 증가. 축소 불가.
  • RDS 읽기 전용 복제본은 자동 확장 없음. Aurora는 Aurora Auto Scaling이 복제본 수를 조정.

Aurora (0021)

클러스터 볼륨AZ 3곳에 사본, 자동 증가, 라이터·리더가 공유
Aurora 복제본최대 15개, 지연 보통 100ms 미만, 장애 조치 대상, 리더 엔드포인트로 분산
Aurora Serverless0.5 ACU 단위 자동 조정, 변동·예측 불가·개발/테스트. 최소 0 ACU → 자동 일시 중지(재개 약 15초)
Global Database보조 리전 최대 10개, 스토리지 기반 복제 1초 미만, 낮은 RPO/RTO, switchover(계획)/failover(장애), 쓰기 전달
스토리지 구성I/O 비용 ≥ 25% → I/O-Optimized, < 25% → Standard

DynamoDB (0022)

온디맨드기본·권장, 요청당 과금, 예측 불가, 0까지 축소
프로비저닝예측 가능·꾸준, 시간당 과금, Auto Scaling(목표 사용률 권장 70%). 1 RCU = 4 KB 강력 일관 1회/초, 1 WCU = 1 KB 1회/초
DAXAPI 호환 캐시, 최종적 일관 읽기를 µs로. 강력한 일관성·쓰기 위주에는 부적합
글로벌 테이블다중 리전 다중 활성(모든 복제본 읽기·쓰기), MREC(기본)/MRSC
Streams항목 변경 로그 24시간, Lambda 트리거
TTLepoch 초 속성, 만료 후 보통 며칠 안에 삭제, 쓰기 용량 소비 없음
PITR최대 35일(1–35 설정) 초 단위 복구. 장기 보관은 온디맨드 백업

비용 한 줄

  • 변동·간헐적 → 서버리스(Aurora Serverless 0 ACU, DynamoDB 온디맨드). 꾸준·예측 가능 → 프로비저닝.
  • EC2 재호스팅은 빠르지만 운영이 남음. "최소 운영 오버헤드" → 관리형(RDS/Aurora).
  • 상용 라이선스 탈피 → Aurora + Schema Conversion + DMS.
