IAM 정책 평가 치트시트

요청 하나가 허용되는지 판정할 때 펼쳐 보는 한 장. 레슨이 늘어날 때마다 단계를 추가합니다.

판정 규칙 (한 계정, 자격 증명 기반 정책)

  1. 기본값은 거부 — 허용이 없으면 암묵적 거부 (루트 사용자 제외)
  2. 일치하는 Allow → 허용 — 사용자 직접 연결 정책과 그룹 정책을 모두 합쳐서 봄
  3. 일치하는 Deny → 거부 — 어떤 Allow보다도 우선

요령: Deny부터 찾는다 → 없으면 Allow를 찾는다 → 없으면 암묵적 거부.

정책이 두 장일 때 (자격 증명 기반 + 리소스 기반)

상황허용 조건
같은 계정둘 중 하나만 Allow해도 허용 (합집합)
└ 예외역할 신뢰 정책 · KMS 키 정책은 그 정책 자체가 명시적으로 허용해야 함
다른 계정요청자 계정의 자격 증명 기반 정책 그리고 리소스 계정의 리소스 기반 정책이 모두 Allow (교집합)

용어

Organizations · SCP · 권한 경계

  1. SCP는 아무것도 허용하지 않는다 — 회원 계정 주체의 최대 권한(상한선)만 정함. 실제 권한은 IAM 정책으로 따로 부여
  2. SCP Allow는 루트→OU→계정 모든 단계에, Deny는 한 단계에만 있어도 — 기본으로 FullAWSAccess가 모든 단계에 붙음
  3. 권한 경계도 상한선, 유효 권한은 교집합 — SCP까지 있으면 SCP ∩ 경계 ∩ 자격 증명 기반 정책
SCP 적용 대상
회원 계정의 IAM 사용자·역할, 회원 계정 루트 사용자적용됨
관리 계정, 서비스 연결 역할, 조직 밖 주체적용 안 됨

평가 순서: 명시적 Deny(모든 정책) → RCP → SCP → 리소스 기반 → 자격 증명 기반 → 권한 경계 → 세션 정책.
