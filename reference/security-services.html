KMS 키 세 종류

고객 관리형AWS 관리형 (aws/서비스)AWS 소유
키 정책내가 통제조회만볼 수 없음
교체선택: 자동(기본 365일, 주기 지정 가능)·온디맨드매년 자동, 변경 불가서비스가 결정
교차 계정 공유키 정책으로 가능불가—
CloudTrail 감사가능가능불가
  • 키 정책이 허용하지 않으면 IAM 정책 Allow는 무효 (같은 계정이어도). 기본 키 정책이 계정에 위임해 IAM 정책을 활성화. 키 정책은 리전 단위.
  • 교체 = 키 자료만 바뀜. 키 ID 그대로, 옛 암호문 자동 복호화, 데이터 재암호화 없음. 비대칭·HMAC·사용자 지정 키 스토어 키는 수동 교체.
  • 삭제: 대기 7–30일(기본 30일), 삭제 후 데이터 복구 불가 → 애매하면 비활성화.
  • 봉투 암호화: 데이터는 데이터 키로, 데이터 키는 KMS 키로. KMS 키는 HSM 밖으로 평문으로 나가지 않음. SSE-KMS 업로드 kms:GenerateDataKey, 다운로드 kms:Decrypt.

S3 암호화

옵션신호
SSE-S3기본값(2023-01-05부터 모든 새 객체 자동 암호화). 별도 요구 없음
SSE-KMS키 사용 감사, 접근 통제, 교체 제어. 비용 절감은 S3 Bucket Key(KMS 요청 비용 최대 99% 절감)
DSSE-KMS이중 계층 서버 측 암호화
SSE-C고객이 요청마다 키 제공, S3는 키 미저장, HTTPS 필수. 새 버킷은 기본 비활성화(2026-04~)
클라이언트 측AWS도 평문을 보면 안 됨
  • HTTPS 강제: 버킷 정책에서 aws:SecureTransport가 false면 Deny.
  • 기본 암호화를 바꿔도 기존 객체는 그대로 → S3 Batch Operations로 복사.

EBS · RDS 암호화

  • 기존 리소스를 바로 암호화할 수 없음. 스냅샷 → 암호화된 사본(또는 새 볼륨) → 복원. 암호화 해제도 불가.
  • EBS 기본 암호화 = 리전별 설정, 기존 볼륨엔 영향 없음.
  • RDS 읽기 전용 복제본은 원본과 암호화 상태가 같아야 함. 다른 리전 복사 시 대상 리전 KMS 키 지정. AWS 관리형 키로 암호화한 스냅샷은 공유 불가.

ACM

  • 통합: ELB, CloudFront, API Gateway 등. 인증서는 리전 리소스(복사 불가), CloudFront는 us-east-1.
  • DNS 검증 + 사용 중 + CNAME 유지 → 자동 갱신. 가져온 인증서는 자동 갱신 안 됨 → 직접 재가져오기, EventBridge로 만료 알림.
