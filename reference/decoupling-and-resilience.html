SQS · SNS · EventBridge (0014)

SQSSNSEventBridge
방식소비자가 폴링, 메시지당 소비자 하나구독자 전원에게 푸시(팬아웃)규칙의 이벤트 패턴으로 라우팅, 규칙당 대상 최대 5개
언제버퍼링, 비동기 작업하나의 이벤트를 여러 곳에, 알림AWS 서비스·SaaS 파트너 이벤트, 일정(Scheduler)
SQS표준FIFO
처리량사실상 무제한초당 300건(배치 시 3,000메시지), 높은 처리량 모드로 확장
전달 · 순서최소 한 번(멱등하게) · 최선 노력정확히 한 번 처리(5분 중복 제거) · 메시지 그룹 안에서 순서
  • 가시성 제한 시간: 기본 30초, 최대 12시간. 처리 시간보다 짧으면 중복 처리. Lambda 소비자는 함수 제한 시간의 6배 이상
  • DLQ: maxReceiveCount 초과 메시지 격리. 원본과 같은 계정·리전·유형. 표준 큐 DLQ 보존 기간은 원본보다 길게
  • 긴 폴링: WaitTimeSeconds > 0, 최대 20초. 빈 응답·비용 감소
  • 보존 기본 4일·최대 14일 · 지연 최대 15분
  • SNS → SQS: 큐 정책이 sns.amazonaws.com에 sqs:SendMessage 허용(+aws:SourceArn). 순서·중복 제거는 SNS FIFO + SQS FIFO(이메일·SMS·HTTP 불가)
  • 큐 깊이로 확장: 대상 추적, 지표 = 인스턴스당 백로그(메시지 수 ÷ InService 수), 목표 = 허용 지연 ÷ 메시지당 처리 시간

리전 · AZ · Route 53 (0016)

  • 리전: 최소 3개 AZ, 리전끼리 격리. 복제하지 않으면 데이터는 다른 리전에 없음
  • AZ: 독립 전력·네트워크의 데이터 센터 묶음, 최대 약 100km 거리, 동기 복제 가능 지연
  • 정적 안정성: 남은 AZ만으로 충분하도록 사전 프로비저닝(6대 필요 → 3 AZ × 3대)
정책키워드
단순리소스 하나
가중치비율, 카나리(가중치 0 = 중단)
지연 시간가장 빠른 리전
장애 조치액티브-패시브, DR
지리 위치사용자 위치, 규정·언어. 기본 레코드 필수(없으면 응답 없음)
지리 근접리소스 위치 + 바이어스(+1~99 확장, -1~-99 축소)
다중 값 응답정상 레코드 최대 8개 무작위, LB 대체 아님
  • 장애 조치 외 정책 + 상태 확인 = 액티브-액티브
  • 상태 확인: 엔드포인트 · 계산된 · CloudWatch 경보. 10/30초 간격, 18% 초과 정상이면 정상. 프라이빗 IP는 CloudWatch 경보 기반
  • 별칭: apex 가능, AWS 리소스 쿼리 무료, IP 변경 자동 반영, Evaluate Target Health. CNAME은 apex 불가

DR (0017)

RPO = 허용 데이터 손실(마지막 복구 지점 이후 최대 시간) · RTO = 허용 다운타임(중단~복원 최대 지연)

전략 (싼 순)DR 리전 상태장애 시
백업 및 복원백업만IaC로 재배포 + 복원
파일럿 라이트데이터 복제·DB 켜짐, 앱 서버 꺼짐켜고 확장
웜 스탠바이축소판 전체 스택 실행 중확장만 (즉시 처리 가능)
다중 사이트 액티브/액티브모든 리전이 운영·트래픽 처리장애 조치 없음, 트래픽 제외
  • 요구를 충족하는 가장 싼 전략이 정답. 다중 AZ만으로 충분한 경우도 많음
  • 복제 ≠ 백업: 손상·삭제도 복제됨 → 특정 시점 백업·버전 관리 병행
  • DR 리전 서비스 할당량 미리 상향, 장애 조치는 데이터 플레인 작업(Route 53 상태 확인)으로, 정기 테스트
  • Aurora 글로벌 DB: 보통 1초 미만 복제, 1분 이내 승격
  • AWS Backup: 백업 계획(태그 할당), 콜드 스토리지 수명 주기, 교차 리전·교차 계정 복사, Organizations 백업 정책. Vault Lock: 거버넌스(IAM 권한으로 해제 가능) / 규정 준수(유예 최소 3일 후 누구도 변경 불가)
